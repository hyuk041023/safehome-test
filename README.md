# Safe Home MVP (규칙 기반 + 문장 해석·특약 설명만 Gemini)

충북대 근처 자취방을 추천하고, 계약 전에 위험 신호를 점검하는 시연용 MVP예요.
노션의 **MVP 설계 (초안)**, **11/10 설문 가중치**, **11/11 회의 제안(예시 계약서 불러오기)**, **11/12 회의 결정(Gemini 연결 방식)**, **11/13 회의(계약서만 분석 + 서류 확인 체크리스트)**를 바탕으로 만들었어요.

> 매물·계약서는 **가상 샘플 데이터**이고, **시세만 국토교통부 전월세 실거래가(실제 공공데이터)**예요. 실제 개인정보는 없어요.

## AI(Gemini) 연결 — 11/12 회의 결정

```
현재:  사용자 문장 → [🤖 AI로 조건 분석] → /api/parse (Vercel 서버리스 함수) → Gemini → 조건 JSON
                                                                         ↓ 실패하면 규칙 해석으로 대신
       입력칸 확인·수정 → [🔎 매물 검색] → SQLite 데이터 검색 → 설문 가중치 점수 → 결과   (Gemini 0회)
```

- **버튼 분리**: 「AI로 조건 분석」은 Gemini를 1번 불러 입력칸만 채워요. 「매물 검색」은 지금 입력칸 값으로만 검색하고 AI를 부르지 않아요.
- **키 위치**: Gemini 키는 브라우저 코드에 없고, Vercel 서버리스 함수(`api/parse.js`)의 환경 변수에만 있어요.
- **AI 역할은 문장 해석과 특약 설명뿐**: 검색·점수·시세 비교·계약 판정은 모두 규칙이에요. AI 답도 허용된 값(정문/중문/후문, 원룸/투룸/오피스텔, 옵션 6종 등)과 숫자 범위만 받아요.
- **실패하면 규칙으로**: 키가 없거나, 한도 초과, 응답 지연(15초), 오류가 나면 안내 문구를 띄우고 규칙 해석으로 채워요. 시연이 멈추지 않아요.

### 키 등록 (팀원이 한 번)

1. [Google AI Studio](https://aistudio.google.com/)에서 API 키 발급 (키는 채팅·노션·GitHub에 붙여 넣지 않아요)
2. Vercel 프로젝트 → **Settings → Environment Variables** → `GEMINI_API_KEY` 추가 (Production·Preview 체크)
3. **Deployments**에서 최신 배포를 **Redeploy** (환경 변수는 다시 배포해야 반영돼요)

### 호출 횟수 제한 (Gemini 무료 한도에 맞춤)

Gemini 무료 한도(11/12 AI Studio 확인): **RPM 15 · TPM 25만 · RPD 500**. 서비스 전체 제한을 이보다 조금 낮게 잡아서 Google 한도에 닿기 전에 먼저 멈춰요. 멈추면 화면은 규칙 해석으로 대신 찾아요.

| 제한 | 기본값 | Google 한도 | 바꾸는 법 (Vercel 환경 변수) |
| --- | --- | --- | --- |
| 서비스 전체 분당 호출 | 12번 | RPM 15 | `LIMIT_GLOBAL_PER_MINUTE` |
| 서비스 전체 분당 토큰 | 20만 | TPM 25만 | `LIMIT_TOKENS_PER_MINUTE` |
| 서비스 전체 하루 호출 | 450번 | RPD 500 | `LIMIT_PER_DAY_TOTAL` |
| 한 번 답의 최대 토큰 | 256 | — | `MAX_OUTPUT_TOKENS` |
| 한 사용자(IP) 분당 | 3번 | — | `LIMIT_PER_MINUTE` |
| 한 사용자(IP) 하루 | 30번 | — | `LIMIT_PER_DAY_IP` |
| 입력 길이 | 200자 | — | `api/parse.js`의 `MAX_CHARS` |
| 화면 한 번 접속당 | 10번 | — | `ai_parse.py`의 `SESSION_LIMIT` |

- 토큰은 Gemini 응답의 `usageMetadata.totalTokenCount`(실제 사용량)로 세요. 부르기 전에는 프롬프트+문장 길이로 어림해서 미리 막아요. 한 번 검색은 약 800~1,000토큰이에요.
- Google이 429(한도 초과)를 주면 **1분 동안 Gemini 호출을 멈춰요**. 그동안은 규칙 해석으로 찾아요.
- 지금 사용량은 `GET /api/parse`로 볼 수 있어요 (오늘 호출 수, 최근 1분 호출·토큰, 쉬는 시간).
- 모델은 `gemini-3.5-flash-lite`예요 (`gemini-2.5-flash`는 새 계정에서 404). 바꾸려면 환경 변수 `GEMINI_MODEL`.
- 한도가 바뀌면(유료 전환 등) AI Studio → **Dashboard → Rate Limit**에서 확인하고, 위 환경 변수를 한도보다 조금 낮게 넣은 뒤 Redeploy 해 주세요.
- 서버 쪽 제한은 함수 메모리에 저장하는 최소한의 방어예요. Vercel이 함수를 새로 띄우면 숫자가 초기화될 수 있어요. 마지막 안전장치는 Google 할당량이고, 넘으면 규칙 해석으로 대신해요.

## 실거래 시세 갱신

```bash
python fetch_market.py   # 인증키를 물어봐요(화면에 안 보임). 키는 저장되지 않아요
```

- 청주시 서원구(개신·사창·성화·모충동) 단독·다가구와 오피스텔 월세 거래 최근 12개월을 받아 `market_prices.csv`(동·유형별 환산 월세 중위값)를 만들어요.
- 원룸 30㎡ 미만, 투룸 30~50㎡로 면적 기준 구분. 거래 3건 미만인 동은 서원구 전체(동별 중위값 가중 평균)로 비교해요.
- 가상 매물 100건의 가격은 이 실제 중위값을 기준으로 만들어요(약 70% 비슷, 15% 싸게, 15% 비싸게). `python db_seed.py`로 다시 만들 수 있어요.

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py        # safehome.db가 없으면 자동으로 만들어요
python test_mvp.py          # 규칙 검증 테스트 (Gemini는 흉내만 내서 키 없이 돌아가요)
python db_seed.py           # DB를 처음부터 다시 만들 때
```

로컬에서 AI 분석까지 쓰려면 `SAFEHOME_API_URL=https://(배포 주소)/api/parse`를 환경 변수로 주고 실행해요. 없으면 규칙 해석만 써요.

## DB 구조 (`safehome.db`)

- `listings` — 가상 매물 (보증금, 월세, 관리비, 넓이, 채광·조용함 1~5, 옵션, 정문·중문·후문 도보 시간, 사례 ID)
- `contracts` — 매물별 **계약서 원문 텍스트** (`contract_text`)
- `cases` — 사례 10종과 기대 판정 (검증표)
- `market_prices` — 동·유형별 시세 (`market_prices.csv`의 실거래 중위값)

## 계약 점검 (11/13 회의)

**가상 계약서만 직접 분석**하고, 계약서로 알 수 없는 서류·집 상태는 **사용자가 직접 확인할 체크리스트**로 따로 보여 줘요.
결과는 계약서 문구만 본 참고 자료예요. "안전·양호"라는 말은 쓰지 않고, 체크리스트는 직접 확인하기 전까지 **미확인**이에요.

### 계약서 분석 (규칙)

모든 항목은 **정상 / 주의 / 위험 / 확인 필요** 중 하나예요. 문서에 값이 없거나 규칙에 없는 문장은 추측하지 않고 **확인 필요**로 보내요.

| 항목 | 기준 | 근거 |
| --- | --- | --- |
| 필수 항목 | 임대인·소재지·보증금·월세·계약기간·작성일 중 빠지면 확인 필요 | — |
| 계약하는 사람 | 대리인 계약이면 🟡 (위임장·인감증명서·소유자 통화) | 민법 제114·130조 |
| 확인·설명 기재 | 납세증명서 '미확인' 🟡, 선순위 보증금·시세·납세 칸이 없으면 확인 필요 | 주임법 제3조의7, 공인중개사법 제25조 |
| 특약 — 전입신고 제한 | 🔴 | 주임법 제3조 제1항(대항력), 제3조의2 |
| 특약 — 보증금 반환 지연(새 세입자 입주 후 반환) | 🔴 | 주임법 제10조(강행규정), 제3조의2 |
| 특약 — 추가 대출·근저당 동의 | 🔴 | 주임법 제3조의2 |
| 특약 — 수리비 전가(범위 없음) | 🟡 | 민법 제623조, 대법원 94다34692 |
| 특약 — 과도한 원상복구 | 🟡 | 민법 제654조·제615조 |
| 특약 — 중도 해지 위약금 | 🟡 | 민법 제398조 제2항 |
| 특약 — 세입자 보호·생활 규칙 | 정상 (담보 설정 금지, 미반환 시 해제, 임대인 수리, 과실 수리, 관리비 항목, 반려동물·흡연 등) | — |
| 특약 — 규칙에 없는 문장 | 확인 필요 + 미리 써 둔 질문 | — |

### AI 특약 설명 (Gemini, 버튼을 누를 때만 1회)

- 특약 문장마다 **확인할 부분(원문 그대로 인용) · 쉬운 설명 · 물어볼 질문**을 받아요.
- 서버와 브라우저에서 두 번 검사해요: 원문에 없는 인용은 지우고, "무효/불법/사기/안전/문제없다"처럼 **단정하는 설명은 버려요**.
- **AI는 판정을 낮추지 못해요.** 규칙이 위험이라고 한 문장은 AI가 괜찮다고 해도 위험이에요. AI는 정상 문장을 '확인 필요'로 올리는 것(후보 찾기)만 할 수 있어요.
- 실패(한도·지연·오류)하면 규칙 결과와 미리 써 둔 설명·질문을 그대로 보여 줘요.

### 직접 확인할 것 (체크리스트, 모두 '미확인'에서 시작)

| 항목 | 왜 | 어디서 | 근거 · 사례(참고) |
| --- | --- | --- | --- |
| 등기사항증명서 | 소유자=임대인, 압류·신탁·근저당·임차권등기 | 인터넷등기소 | 신탁법 제4조, 주임법 제3조의2 · 관리인 사칭, 대구 신탁 |
| 선순위 보증금 (확정일자 부여 현황) | 다가구는 다른 세입자 보증금이 먼저 배당 | 임대인 제시·주민센터 | 주임법 제3조의6·3조의7·3조의2·8조 · 대전 선순위 허위 고지 |
| 집주인 세금 체납 | 체납 세금이 보증금보다 먼저 배당될 수 있음 | 임대인 제시·세무서 | 주임법 제3조의7, 국세징수법 제109조 · 미납 세금 미회수 통계 |
| 건축물대장 | 위반건축물, 용도, 호수 | 정부24 | 건축법 제79조 · 학생 불법건축물 계약 |
| 대리인 권한 (대리인 계약일 때만) | 권한 없는 사람과 계약 | 소유자 직접 | 민법 제114·130조 |
| 중개사무소·확인설명서 | 등록 여부, 서면 설명서 | 국가공간정보포털 | 공인중개사법 제25조 · 중개사 허위 설명 송치 |
| 현장 상태 | 누수·곰팡이·보일러·방범·소음, 입주 사진 | 직접 방문 | — |

- 매물 유형에 따라 바뀌어요: 원룸·투룸(다가구)은 선순위 보증금이 **꼭 확인**, 오피스텔은 호실 기준 안내. 계약서에 납세증명서 '미확인'이면 세금 항목이 **꼭 확인**으로 올라가요.
- 선순위 보증금 항목에 **보증금 비율 계산기**가 있어요: (등기부 근저당 + 선순위 보증금 + 내 보증금) ÷ 시세. 팀 기준 70% 주의·80% 위험이며 공식 기준이 아니에요.
- 근거 법령: 주택임대차보호법 현행 법률 제21065호(2026.1.2 시행), 제3조의7은 법률 제19356호(2023.4.18 공포)로 신설. 실제 사례는 노션 「전세사기 관련 법률 지식 및 실제 사례 조사」에서 가져왔고 **참고용이며 사기 판단 근거가 아니에요**.

## 테스트 결과와 한계 (시연·발표에 그대로 써요)

- **표현 바꾸기**: 위험·주의 특약 19문장(같은 뜻 다른 표현) 모두 탐지, 세입자 보호·생활 규칙 9문장 오탐 0개 (`test_mvp.py` [8]).
- **찾은 오탐(고침)**: "임차인은 임대인이 수리하지 않는 경우에도 이의를 제기하지 않는다"가 '임대인 수리(세입자 보호)'로 정상 처리되던 것을 테스트로 찾아 고쳤어요. 지금은 '확인 필요'.
- **알려진 미탐(한계)**: 아래 문장은 사람이 보면 위험·주의지만 규칙은 **확인 필요**로만 표시해요 (최소한 정상으로 넘기지는 않음). AI 설명이 보완해요.
  - "임대인 사정상 주소지는 다른 곳으로 유지해 주세요." (전입신고 제한)
  - "보증금 반환은 임대인 형편에 따라 조정할 수 있다." (보증금 반환 지연)
  - "임차인은 임대인이 수리하지 않는 경우에도 이의를 제기하지 않는다." (수리비 전가)
- 규칙에 없는 문장은 모두 '확인 필요'라서, 평범한 특약이 많으면 확인 필요가 늘어날 수 있어요(보수적).
- 계약서 형식이 `키: 값`·`[특약사항]` 번호 목록이 아니면 읽지 못해요. 실제 계약서·OCR은 후속 검토 대상이에요.
- 결과는 계약서 문구만 본 것이에요. 등기·세금·선순위·건물·현장은 직접 확인하기 전까지 알 수 없어요. 법률 자문이 아니에요.
